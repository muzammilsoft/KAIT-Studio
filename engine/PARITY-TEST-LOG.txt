Gradle client could not complete a build: the daemon process starts and
listens on 127.0.0.1, the client reports "Connected to address /127.0.0.1",
yet the daemon never logs an accepted connection and the client fails after
~20ms with "Could not receive a message from the daemon" (tried 4 times,
daemon + single-use modes, -Xmx256m, fresh GRADLE_USER_HOME). Loopback TCP
itself works in this sandbox (verified Java->Python and Python->Python, and
a raw probe to the daemon port was accepted and logged). So the failure is
specific to the Gradle client<->daemon handshake in this sandbox, not to the
project. On a normal machine (or KG's CI) `./gradlew test` is the command to
run; the standalone run above is the same verification executed directly.
(Note: the untrained model's generate() output contains raw control bytes
from sampled byte-tokens; one NUL byte was stripped from this log so the
file stays plain text. The test assertions themselves are unaffected.)
